## 一、项目简介

"花海"是一个面向大学生群体的**跨校校园活动聚合与质量监管平台**。它把分散在各个高校讲座通知、社团招新、比赛报名、志愿招募等活动信息统一聚合到一站式的平台上，学生可以跨校浏览、报名、收藏任何学校的活动；同时平台通过**报名实名制 + 活动结束后评分评价 + 佣金与服务费挂钩**的机制，对活动质量进行全流程监管，让学生"敢报名、不踩坑"，让优质活动获得更多曝光。

项目已完成第一版核心系统的开发并本地部署运行，实现了注册登录、活动浏览检索、在线报名、星级评分、活动收藏、个人中心、会员体系、活动推广等完整功能闭环，具备继续深化开发的坚实研究基础。

## 二、项目背景与市场分析

### 2.1 痛点分析

大学生校园活动信息目前存在"三散三难"：

1. **信息散**：讲座、比赛、志愿、社团活动分散在海报、群聊、公众号、辅导员转发等多个渠道，学生需要到处打听，经常错过心仪活动；
2. **资源散**：各高校活动互不开放，名校的优质讲座、比赛资源外校学生难以知晓和参与，优质资源利用率低；
3. **监管散**：活动质量参差不齐，收费活动"货不对板"无人追责，学生报名后体验差也没有公开的评价渠道。

由此带来"三难"：**发现难**（找不到好活动）、**参与难**（跨校活动报名渠道缺失）、**避坑难**（没有可信的活动质量参考）。

### 2.2 需求调研

团队面向本校及周边高校开展了需求调研（问卷数据与访谈记录见附件，正式申报时补充完整数据），核心发现：

- 绝大多数受访学生表示"每周都会关注校园活动，但主要依赖群聊和海报"；
- 多数受访者曾有"报名的活动名不副实"的经历，表示"如果能看到往期参与者的真实评分，会显著提升报名意愿"；
- 受访学生普遍欢迎"跨校参加优质活动"，尤其是讲座论坛和科技竞赛类。

### 2.3 竞品分析

| 竞品类型 | 代表 | 局限 |
|---------|------|------|
| 校内官方渠道 | 学校官网、公众号 | 仅本校信息，无跨校聚合，无评价体系 |
| 社群工具 | QQ群、微信群 | 信息淹没快、无沉淀、无报名管理 |
| 商业活动平台 | 活动行、互动吧 | 面向社会人群，校园活动渗透率低，无校园质量监管机制 |
| 校园社交产品 | Super校园等 | 以社交为主，活动只是附属模块，缺乏质量监管设计 |

**差异化定位**：花海聚焦"跨校聚合 + 质量监管"两个竞品均未做深的维度，以评分监管建立信任壁垒，以跨校聚合建立资源壁垒。

## 三、项目创新点

1. **跨校活动聚合**：打破单一学校信息孤岛，按学校、分类、关键词多维检索活动，支持"以活动找学校、以学校找活动"的双向浏览体验，让优质教育资源跨校流动；
2. **活动质量全流程监管体系**（核心创新）：
   - **实名报名制**：报名与学籍账号绑定，杜绝刷报名数据；
   - **参与后评分制**：只有真实报名参与的用户才有评分资格（1~5 星 + 文字评价），从机制上杜绝水军刷分，评分数据真实可信；
   - **经济杠杆调节**：平台对收费活动收取服务费，会员用户享受费率优惠，推广位费用与会员等级挂钩，形成"优质活动方愿意付费推广、平台用服务费反哺监管"的良性循环；
3. **会员与推广生态**：校园会员（campus）与高级会员（premium）双级体系，活动发布者可购买首推位推广，平台按会员等级提供差异化佣金折扣，构建可持续的校园活动商业生态；
4. **轻量级全栈技术方案**：不依赖重型框架，采用 Java 17 原生 HttpServer + SQLite + 原生前端三件套实现完整前后端分离架构，部署成本极低（一台普通服务器即可），适合校园场景快速落地与推广。

## 四、项目内容与功能规划

### 4.1 已完成功能（第一版核心系统，已部署运行）

**用户体系**
- 注册（账号格式校验、密码强度实时提示、手机号格式校验）
- 登录（"记住账号"、登录态 Token 鉴权、会话管理）
- 个人中心（资料编辑、密码修改、我的报名 / 我的收藏 / 我发布的活动三大清单）

**活动体系**
- 活动浏览：首页推荐位 + 全部活动列表，按分类（讲座论坛 / 体育竞技 / 文艺演出 / 科技创新 / 志愿公益 / 社交聚会）筛选，关键词搜索
- 活动详情：时间地点、报名费、平台服务费与发布者实得金额透明展示
- 在线报名：满员校验、重复报名拦截、防重复提交
- 星级评分：参与后评分（1~5 星 + 评价），平均分与评分人数实时统计
- 活动收藏：一键收藏 / 取消，收藏列表集中管理

**会员与推广体系**
- 双级会员（校园达人 / 活动达人）购买与状态展示
- 活动推广套餐（基础 / 高级 / 旗舰 × 天数），会员折扣自动计算，首推位展示

**工程质量**
- 前端公共组件库（登录态管理、API 请求封装、XSS 转义防护、防连点）
- 后端分层架构（路由控制 → 业务服务 → 数据访问 → 连接池），统一 JSON 响应与异常处理

## 五、技术方案与系统架构

### 5.1 技术选型

| 层次 | 技术 | 选型理由 |
|------|------|---------|
| 后端 | Java 17 + JDK 内置 HttpServer | 零框架依赖、内存占用小、部署简单，适合校园低成本服务器 |
| 数据库 | SQLite（WAL 模式）+ 自研连接池 | 单文件数据库免安装，读写性能满足校园规模，后续可平滑迁移 MySQL |
| 前端 | 原生 HTML5 / CSS3 / JavaScript | 无构建链、加载快、学习维护成本低，符合 Web 标准化趋势 |
| 鉴权 | Bearer Token + 服务端会话表 | 无状态请求头鉴权，接口风格与主流开放平台一致 |

### 5.2 系统架构

```
┌─────────────────────────────────────────────┐
│  浏览器（8+ 静态页面，localStorage 登录态）    │
└──────────────────┬──────────────────────────┘
                   │ HTTP / JSON
┌──────────────────▼──────────────────────────┐
│  路由控制层 RouterController                  │
│  ├─ 静态资源服务（路径穿越防护）               │
│  ├─ 认证拦截器 AuthInterceptor（Token 校验）  │
│  └─ REST API 路由分发                        │
├─────────────────────────────────────────────┤
│  业务服务层 Service                           │
│  ├─ 用户服务（注册 / 登录 / 资料 / 会员）       │
│  └─ 活动服务（发布 / 报名 / 评分 / 收藏 / 推广）│
├─────────────────────────────────────────────┤
│  数据访问层 DAO（参数化 SQL，防注入）           │
├─────────────────────────────────────────────┤
│  数据库连接池 DbPool + SQLite（WAL）           │
└─────────────────────────────────────────────┘
```

### 5.3 核心数据库表

`users`（用户：账号、密码、昵称、学校、手机、会员等级与到期时间）、`activities`（活动：名称、分类、时间地点、人数上限、报名费、发布者、标签、推广信息）、`signups`（报名记录：活动、用户、时间）、`ratings`（评分：星级、评价内容）、`favorites`（收藏）、`sessions`（登录会话）。

### 5.4 核心 REST API（节选）

```
POST /api/register          注册
POST /api/login             登录（返回 Token）
GET  /api/user              获取个人信息
POST /api/user/update       修改资料 / 密码
GET  /api/activities        活动列表（关键词 + 分类筛选）
POST /api/activities        发布活动（会员权限校验）
POST /api/activities/{id}/signup    报名（满员/重复校验）
POST /api/activities/{id}/rate      参与后评分
POST /api/activities/{id}/favorite  收藏切换
POST /api/vip/buy           购买会员
POST /api/promote/buy       购买推广
```

## 十一、风险分析与应对

| 风险 | 应对措施 |
|------|---------|
| 跨校合作推进不及预期 | 先做深本校运营形成标杆案例，以数据说服外校；同步支持"个人发布"降低组织入驻门槛 |

| 用户增长缓慢 | 结合迎新季、社团招新季等节点地推；报名流程相比群接龙更便捷，以体验换口碑 |
| 技术迭代风险 | 架构分层清晰、数据库可平滑迁移 MySQL，预留水平扩展空间 |

## 十二、项目运行说明

**环境要求**：JDK 17+（推荐 21），Windows / Linux 均可。

**快速启动**（项目根目录执行）：

```bash
# 编译（依赖 jar 已在 lib/ 目录）
javac -encoding UTF-8 -cp "lib/slf4j-api.jar;lib/slf4j-simple.jar;lib/sqlite-jdbc.jar" -d target/classes $(find src/main/java -name "*.java")

# 启动
java -cp "target/classes;lib/slf4j-api.jar;lib/slf4j-simple.jar;lib/sqlite-jdbc.jar" com.campus.NirvanaFlower
```

启动后访问 `http://localhost:8080`，数据库 `campus_activity.db` 自动初始化并写入示例数据。

**演示账号**：`demo / 12345678`（高级会员）、`test / 12345678`（校园会员）。

**目录结构**：

```
├── src/main/java/com/campus/   后端源码（api / config / control / dao / service / model）
├── html/                       前端页面（9 个）
├── css/  js/                   样式与脚本（common.js 为公共组件库）
├── lib/                        依赖 jar（sqlite-jdbc、slf4j）
└── campus_activity.db          SQLite 数据库（首次运行自动创建）
```
